## 第一章 需求分析

### 1.1 开发背景与目的

视障及低视力群体在独立步行出行与读取近距离文字（如路牌、包装说明）时，对 **多模态反馈（语音 + 震动）** 与 **无障碍界面** 需求突出。现有通用地图应用读屏体验与风险提醒方式未必贴合该群体的高频场景。本项目旨在开发一款 Android 端应用，集成 **地图步行导航**、**风险提示与路口相关信息展示**、**图像文字识别与朗读**，并在系统层面落实 **隐私同意、配置校验、权限引导**，以提升可用性与合规性。

### 1.2 用户与场景

- **主要用户：** 视障/低视力用户。
- **次要用户：** 家属或陪护人员（协助配置）、测试与运维人员。
- **典型场景：** 室外步行至目的地；路口通行辅助；对药品标签、门牌等短文本进行识读。

### 1.3 主要功能（与竞品对比维度简述）

| 维度 | 本项目侧重点 | 说明 |
| --- | --- | --- |
| 无障碍 | 高对比 UI、TalkBack 语义、动态可读区域 | 面向读屏与弱视力用户优化 |
| 多模态输出 | TTS + 震动，仲裁器统一优先级 | 降低多通道同时播报的混乱 |
| 出行 | 百度地图 SDK 步行导航 + 叠加层（障碍/灯态等，随版本演进） | 与通用地图互补，强调辅助叙事 |
| 识图 | 云端视觉接口（Ark 等，见构建配置） | 与纯离线 OCR 方案在隐私与依赖上各有取舍 |

详细需求见 `PRD.md`；实现细节与当前行为以 `使用说明-详细版.md` 为准。

### 1.4 主要性能与非功能需求

- 启动阶段 **门禁流程** 可理解、可恢复；配置缺失时 **明确提示**，避免静默失败。
- 导航状态机约束 UI 与异步任务（如可取消的路线规划），减少并发冲突。
- OCR 端侧 **图像压缩** 再上送，控制请求体积与弱网体验。

## 第二章 概要设计

### 2.1 功能模块划分

```text
┌─────────────────────────────────────────────┐
│                    UI（Compose）             │
│  首页 │ 导航 │ OCR │ 设置 │ 帮助 │ 启动门禁   │
└─────────────────────┬───────────────────────┘
                      │
┌─────────────────────▼───────────────────────┐
│  domain（用例、仲裁事件、设置/隐私交互）      │
└─────────────────────┬───────────────────────┘
                      │
┌─────────────────────▼───────────────────────┐
│  data（Settings/Privacy 等仓库实现）        │
└─────────────────────┬───────────────────────┘
         ┌────────────┴────────────┐
         ▼                         ▼
  百度地图/定位/语音等          CameraX / 网络 API
```

### 2.2 层次与依赖关系

- **ui：** 页面与交互；通过 ViewModel 持有 UI 状态。
- **domain：** `SettingsInteractor`、`PrivacyConsentInteractor`、仲裁相关模型等。
- **data：** `SettingsRepositoryImpl`、`PrivacyRepositoryImpl` 等持久化与策略。
- **utils / navigation：** `Arbitrator`、`TTSManager`、导航服务、权限与配置校验等。

依赖注入采用轻量 **`AppContainer`**（手动 DI），便于测试替换实现。

### 2.3 人机界面与关键流程（文字概要）

- **启动：** 隐私页 → 配置校验 → 权限引导 → `NavHost` 主页。
- **导航：** 状态机（待机 → 监听 → 规划 → 导航 → 暂停/到达等）驱动界面与播报。
- **OCR：** 预览 → 拍照/相册 → 识别 → 展示/复制/重播。

## 第三章 详细设计

### 3.1 界面与交互要点

- **Material3 + 自定义高对比主题**，核心控件配置 `contentDescription`。
- **导航页** 底部控制栏承载「下一步/暂停/继续/结束」等（以当前代码为准）。
- **OCR 页** 提供拍照、相册、闪光灯、结果区与复制/重播。

### 3.2 数据设计

本应用 **无独立服务端数据库**；用户侧数据主要为 **SharedPreferences/DataStore 类持久化**（设置项、隐私同意状态等）。不设 ER 图；若后续增加账号与云端同步，需单独补充数据模型与隐私评估。

### 3.3 关键技术

1. **仲裁器（`Arbitrator`）**  
   接收 `AccessibilityEvent`，按优先级 **障碍 > 导航 > OCR > 信息** 统一调度 TTS 与震动，避免多模块抢占。

2. **导航状态机**  
   约束语音监听、路线规划与地图生命周期，规划任务可取消，避免旧结果覆盖新请求。

3. **OCR 链路**  
   CameraX 采集 → 端侧缩放/压缩 → Base64 等格式请求云端识别 → 结果驱动 UI 与 TTS。

4. **合规门禁**  
   `ConfigValidator` 检测占位符密钥；双隐私同意；权限永久拒绝时引导至系统设置。

## 第四章 测试报告

### 4.1 测试用例与范围

系统化用例见 **`测试用例-EarRove.md`**，覆盖启动门禁、首页、导航状态、OCR、设置、无障碍与仲裁场景等。

### 4.2 测试执行方式

```bash
./gradlew :app:testDebugUnitTest
./gradlew :app:connectedDebugAndroidTest
./gradlew ktlintCheck
```

（Windows 将 `./gradlew` 换为 `.\gradlew.bat`。）

### 4.3 结果与指标（定性）

| 维度 | 结论方向 |
| --- | --- |
| 可用性 | 门禁与异常路径有文案与语音/读屏支撑；拒权与弱网需真机回归 |
| 安全性 | 密钥经 `local.properties` 注入，不入库；需防止调试包泄露密钥 |
| 扩展性 | 分层与 `AppContainer` 便于替换 Fake；交通灯等可替换数据源 |
| 部署 | 标准 Gradle 构建；依赖本地 `app/libs` 与网络仓库 |

具体缺陷列表与截图宜在团队内部测试平台维护，本文档仅作概要。

## 第五章 安装及使用

### 5.1 环境要求（开发构建）

- JDK 11、Android Studio、Android SDK（`compileSdk`/`targetSdk` 以 `app/build.gradle.kts` 为准）。
- 在仓库根目录由 `config.sample.properties` 复制为 `local.properties` 并填写地图、语音、Ark 等密钥。

### 5.2 安装步骤摘要

```bash
./gradlew :app:assembleDebug
./gradlew :app:installDebug
```

### 5.3 典型使用流程（最终用户）

详见同目录 **`用户手册.md`**；技术向说明见 **`使用说明-详细版.md`**。

## 第六章 项目总结

本项目在 **无障碍出行 + OCR 朗读** 方向完成端到端闭环，实践中在 **多语音源仲裁**、**地图与 Compose 生命周期**、**合规与权限路径** 上投入较多精力。后续可演进：交通灯数据源实网化、更强 DI 框架、导航状态机自动化测试、弱网离线策略等。团队协作上适合按 **数据/领域/UI** 分层拆分任务，并以真机无障碍验收作为发布门禁之一。
