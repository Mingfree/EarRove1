# EarRove（聆途）详细使用说明与设计文档

> 面向对象：开发者、测试人员、产品同学、项目交接人员  
> 项目定位：视障辅助 Android 应用，核心场景为“无障碍出行导航 + 视觉文字识别”

---

## 1. 项目简介

`EarRove` 是一个基于 Android + Kotlin + Jetpack Compose 的视障辅助应用，重点提供以下能力：

- 导航辅助：语音输入目的地、步行路径规划、路线指引、路口信息提示。
- 风险提醒：导航中叠加障碍预警与交通灯提示。
- OCR 识别：通过拍照或相册识别图中文字并语音播报。
- 无障碍体验：TalkBack 语义标注、高对比主题、语音+震动双通道反馈。
- 合规门禁：隐私同意、关键配置校验、启动权限引导。

## 2. 目标用户与典型场景

### 2.1 目标用户

- 视障用户（全盲/低视力）。
- 家属或陪护人员（用于预配置、调试）。
- 开发与测试团队（功能验证、回归测试）。

### 2.2 典型使用场景

- 室外步行导航：通过语音输入目的地进行逐步引导。
- 过路口辅助：结合交通灯信息与语音提示。
- 近距离文字读取：识别药品说明、门牌路牌、包装标签等文字。
- 设置辅助：调节语速、振动与家庭地址。

## 3. 技术栈与运行环境

### 3.1 技术栈

- 语言：Kotlin
- UI：Jetpack Compose + Material3
- 架构：轻量分层（`data/domain/ui`）+ 手动 DI（`AppContainer`）
- 地图导航：百度地图 SDK（本地 `app/libs`）
- 相机：CameraX
- 语音交互：TTS、语音识别（项目内多服务组合）
- OCR：基于 Ark 视觉识别接口（通过 API Key 注入）
- 构建：Gradle + AGP + ktlint

### 3.2 环境要求

- JDK 11
- Android Studio（建议稳定版）
- Android SDK：
  - `compileSdk = 36`
  - `targetSdk = 36`
  - `minSdk = 26`
- 建议真机调试（涉及定位、麦克风、相机、系统权限）

## 5. 首次部署与启动流程

## 5.1 克隆与打开工程

```bash
git clone <你的仓库地址>
cd EarRove227
```

Android Studio 打开项目根目录，等待 Gradle 同步完成。

### 5.2 本地密钥配置（必须）

项目通过 `local.properties` 注入敏感信息，避免硬编码入仓库。

示例流程（Windows PowerShell）：

```powershell
Copy-Item config.sample.properties local.properties
```

在 `local.properties` 中填写真实值：

- `DASHSCOPE_API_KEY`
- `BAIDU_MAP_API_KEY`
- `BAIDU_SPEECH_APP_ID`
- `BAIDU_SPEECH_API_KEY`
- `BAIDU_SPEECH_SECRET_KEY`
- `BAIDU_TTS_API_KEY`
- `BAIDU_TTS_SECRET_KEY`
- `ARK_API_KEY`

> 说明：`app/build.gradle.kts` 会将上述项注入 `BuildConfig` 与 `manifestPlaceholders`。

### 5.3 构建安装

```powershell
.\gradlew.bat :app:assembleDebug
.\gradlew.bat :app:installDebug
```

## 6. 启动门禁与合规机制（重点）

应用启动后并不是直接进入主页，而是按顺序通过 3 道门禁：

1. **隐私同意门禁**
   - 需分别同意“应用隐私政策”与“百度地图隐私政策”。
   - 仅当双同意后才放行主流程。
2. **配置有效性门禁**
   - `ConfigValidator` 检测关键配置是否仍是占位符（如 `YOUR-*`）。
   - 配置缺失时给出明确修复提示与重试按钮。
3. **运行权限门禁**
   - 核心权限：定位、相机、麦克风。
   - 可引导继续（降级体验）或前往系统设置修复永久拒绝权限。

## 7. 功能使用说明（面向最终使用）

## 7.1 首页

首页分为三部分：

- 上半区：导航入口。
- 下半区：OCR 入口。
- 底部栏：设置与帮助入口。

支持较完整 TalkBack 语义标签。

### 7.2 导航功能使用

导航页采用状态机驱动：

- `STANDBY`：待机，等待目的地输入。
- `LISTENING`：语音监听中。
- `PLANNING_ROUTE`：路线规划中。
- `NAVIGATING`：导航进行中。
- `PAUSED`：导航暂停。
- `ARRIVED`：已到达。

基础操作流程：

1. 进入导航页并确保权限通过。
2. 语音输入目的地，系统解析目标地点。
3. 等待路线规划完成，进入导航过程。
4. 通过底部控制栏执行“下一步/暂停/继续/结束导航”。
5. 到达后进入到达态并支持返回。

导航叠加提示：

- **障碍警示层**：高优先级覆盖提醒。
- **交通灯提示层**：显示红绿灯状态与倒计时。

> 注意：当前 `TrafficLightService` 中含模拟逻辑（随机信号），适合开发与演示阶段验证 UI 与语音链路。

### 7.3 OCR 功能使用

进入 OCR 后主要有三类操作：

- 拍照识别（主按钮）
- 相册选图识别（图库按钮）
- 闪光灯开关（补光按钮）

识别结果区支持：

- 复制文本到剪贴板
- 一键重播识别文本（TTS）

OCR 交互要点：

- 首次进入会播报引导语。
- 识别状态、成功/失败状态都会有文本与语音反馈。
- 结果区域使用 live region，提升读屏动态可感知性。

### 7.4 设置功能使用

设置页支持：

- TTS 语速滑块（0.5~2.0）
- 震动开关
- 隐私撤回（弹窗确认）
- 家庭地址设置、保存与清空

设置由 `SettingsViewModel` + `SettingsInteractor` + `SettingsRepository` 管理，状态可持久化。

### 7.5 帮助中心

帮助页提供导航、OCR、震动反馈的说明文本，适合首次学习与家属指导。

## 8. 系统设计说明（架构视角）

### 8.1 分层思想

1. `ui`：界面展示与交互（Compose）。
2. `domain`：业务模型和用例（`SettingsInteractor`、`PrivacyConsentInteractor`、`AccessibilityEvent`）。
3. `data`：持久化与 SDK 细节封装（`SettingsRepositoryImpl`、`PrivacyRepositoryImpl`）。
4. `utils/navigation`：跨模块工具与业务服务（TTS、仲裁、导航、定位、权限等）。

### 8.2 依赖注入策略

- 使用轻量手动 DI：`MyApplication.container`（`AppContainer`）。
- 统一提供设置和隐私仓库/用例单例。
- ViewModel 优先从 `AppContainer` 获取依赖，失败时降级本地构造（容错）。

### 8.3 主流程状态控制

- `MainActivity` 首屏只负责决定“协议页 or 主应用”。
- `StartupConfigAndPermissionGate` 负责配置/权限门禁。
- `EarRoveApp` 负责 NavHost 挂载及地图 SDK 初始化等待策略（含超时降级）。

### 8.4 导航模块设计

组成：

- `NavigationScreen`：状态机 + 交互编排 + 地图容器。
- `NavigationService`：路线规划、当前步骤、地图路线绘制。
- `LocationManager`（工具类）：定位数据来源。
- `ObstacleDetectionService`：障碍信号输入（与仲裁器联动）。
- `TrafficLightService`：交通灯状态来源（当前可模拟）。

关键设计点：

- 以状态机减少“语音、定位、地图并发”导致的界面冲突。
- 路线规划使用可取消任务，防止旧请求覆盖新请求。
- 权限永久拒绝时给出明确“去系统设置”修复路径。

### 8.5 OCR 模块设计

组成：

- `OcrScreen`：摄像头预览、拍照、相册、状态与结果展示。
- `OcrViewModel`：状态流与识别调用。
- `VolcengineArkService`：识别请求。

关键设计点：

- 图片在端上压缩（宽度上限）后转 Base64，减少请求体积。
- 操作状态统一收敛到 `OcrUiState`，避免 UI 线程散乱更新。
- 提供复制/重播，提高结果复用效率。

### 8.6 音频与震动仲裁设计

`Arbitrator` 统一接收 `AccessibilityEvent` 并按优先级处理输出：

- 优先级：`OBSTACLE > NAVIGATION > OCR > INFO`
- 同时可能触发：
  - 语音播报（`ArbitrationSpeech`）
  - 震动反馈（`ArbitrationHaptics`）

收益：

- 避免多个模块直接抢占 TTS/震动导致提示混乱。
- 规则集中，便于后续扩展事件类型与优先级。

### 8.7 隐私与配置设计

- 配置注入：`BuildConfig` + Manifest 占位符，避免硬编码。
- 启动自检：拦截占位符配置，防止“运行时静默失败”。
- 双隐私同意：应用协议与地图协议分开存储，状态更明确。
- 设置页支持隐私撤回，满足用户控制权与合规要求。

## 9. 权限与硬件依赖说明

主要权限（`AndroidManifest.xml`）：

- 定位：`ACCESS_FINE_LOCATION` / `ACCESS_COARSE_LOCATION`
- 网络：`INTERNET` / 网络状态权限
- 相机：`CAMERA`
- 麦克风：`RECORD_AUDIO`
- 震动：`VIBRATE`
- 存储（兼容历史逻辑）：`READ_EXTERNAL_STORAGE` / `WRITE_EXTERNAL_STORAGE`

硬件特性：

- 摄像头与自动对焦
- GPS 与位置能力
- 加速度计、指南针

## 10. 无障碍设计要点

项目已落实的无障碍方向：

- 高对比主题（黑底+高亮文本）
- 核心控件 `contentDescription`
- 动态提示使用 live region（如导航状态、OCR状态）
- 关键按钮焦点遍历顺序控制（`traversalIndex` / `isTraversalGroup`）
- 语音与震动结合，覆盖纯语音不可听清场景

建议验收：

- 使用 TalkBack 完整走通：首页 -> 导航 -> 设置 -> OCR。
- 验证权限拒绝、隐私撤回、识别失败等异常路径是否可理解可恢复。

## 12. 常见问题与排障

### 12.1 启动提示缺少配置

- 原因：`local.properties` 未配置或仍为占位符。
- 处理：按第 5.2 节补齐 key，重新构建安装。

### 12.2 导航页无法进入/地图初始化失败

- 先确认：百度地图隐私已同意、定位权限已授权。
- 再确认：`BAIDU_MAP_API_KEY` 有效且网络可用。
- 如仍失败：重启应用，观察是否进入 SDK 重初始化分支。

### 12.3 OCR 无法识别

- 检查相机权限。
- 确认网络连通（若识别服务依赖云端）。
- 适当补光并保持画面稳定。

### 12.4 语音播报异常

- 检查 TTS key 配置。
- 查看是否被高优先级事件（如障碍警告）抢占。

### 12.5 震动不生效

- 检查设置页震动开关。
- 检查系统震动权限与设备震动马达是否可用。

## 13. 安全与发布注意事项

- 严禁提交真实密钥到仓库。
- 发布前必须跑无障碍清单、权限拒绝路径和隐私撤回路径。
- 建议保留调试日志级别开关，线上构建降低敏感日志输出。
- 建议逐步移除不再需要的高风险权限（如旧版存储权限）以降低审核风险。
